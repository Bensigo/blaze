# Web game marketing — implementation context

Approved 28 October 2026. Independent Blaze product at `/Users/macbook/work/web-game-marketing`, now served on its separate permanent Netlify site. Forever is the intended first integration; work in its own project is separately scoped and its real integration is not yet accepted.

## Product decisions

Web games only. Multi-game workspaces, Google login, server-held user provider keys. Own telemetry SDK. Human traffic is separated from synthetic recordings. Jev selects bounded actions from a game state/action adapter while a browser worker records real gameplay. Video recordings feed a reusable clip library, drafts, review, calendar, and approved publication. Daily in-product jobs inspect discoverability, public research sources, competitors, and telemetry; findings cite observations and distinguish hypotheses. No unreviewed publication, billing plans, spend, paid resource upgrades, or native store optimization.

## Architecture

The in-product research agent uses Vercel AI SDK 7 `ToolLoopAgent` with read-only evidence/history tools, structured proposals, a four-step limit and a 12-second deadline. Content drafts and research interpretation use the same SDK with the workspace's explicit Anthropic or OpenRouter provider/model selection and encrypted key. Fresh per-game history includes bounded 90-day human aggregates, observed campaign traffic, prior post copy/status, past findings and measured changes. Raw player/session identifiers, credentials and private capture footage are excluded. Missing model access remains an explicit coverage gap; deterministic checks still run. AI suggestions require review, and no model tool can approve or publish. Jev uses OpenRouter's System One decision API with a separately selected OpenRouter key and pinned Jev model for gameplay.

Next.js 16.4.3 App Router + TypeScript on https://blaze-bensigo.netlify.app. The existing free Neon PostgreSQL project provides the managed database, Managed Better Auth with the owner's dedicated Google OAuth client, and private S3-compatible media storage. The owner completed Google sign-in; a namespaced Neon identity and the signed-in empty workspace were observed. Independent clean-refresh/logout acceptance remains incomplete. Provider identities map to server-owned workspaces; opaque local sessions and the development login are disabled in production. PGlite is local development/test storage. AES-256-GCM encrypts provider credentials.

The SDK validates game origins, bounds and deduplicates events, and separates authenticated synthetic traffic from the human-event protocol. Controlled browser tests are isolated from the owner's workspace; the protocol's human label is not bot detection. The real Forever connection is intentionally awaiting the user's notice that its manifest endpoint is live. Do not probe, modify or deploy that endpoint meanwhile.

The Netlify team remains Free Legacy, with the existing Ryla site and plan preserved. Actual entitlements include 125,000 monthly function calls, 100 GB-hours, 100 GB bandwidth and 300 build minutes. These shared limits do not guarantee 100,000 events/day; no card, trial, paid upgrade or recharge is approved. Runtime configuration uses an explicit allowlist and excludes the project-scoped Neon administrative key. Cloudflare full-app and Neon Functions website-hosting experiments are superseded by the working native Next.js host.

Private Neon media staging/final-copy, anonymous denial, Range playback and the local isolated Docker worker's actual recording/screenshot/MP4 pipeline passed on the permanent host. Media durations and observation timestamps are bounded by the encoded media duration. That controlled worker is stopped; no always-on host or live Jev validation is established. Authenticated daily dispatch queues a durable background consumer; a manual dispatch completed while the local worker was stopped. The 06:00 UTC schedule is registered, but its clock-triggered execution has not been observed. The old Blaze Vercel cron is disabled.

Adding a game durably queues a source-backed profile investigation. Owner overrides are kept separately, and missing evidence or integrations remain visible. Human telemetry can trigger a coalesced profile refresh. Automatic Jev recording defaults to a 24-hour interval only after a prior same-game recording proves real actions and a Jev decision, with a verified key, recent worker heartbeat and investigated profile; the owner can pause it. Actual clips can feed a draft from the selected AI provider when the configured model is available, but drafts require review and are never automatically approved. This readiness is historical evidence, not proof of current provider availability.

The reader vendors the full Forever v1 producer validator from b7aafab4, uses pinned public DNS/IP validation, follows no redirects and enforces time/body limits. Missing, invalid, hidden and unsupported manifests produce useful errors. Manifest id/slug and opaque Blaze game ID remain distinct. The producer endpoint belongs to Forever's owner and is intentionally not live yet; await the user's notice before further live checks. Already queued legacy page-metadata jobs retain their original page URL and source label. Owner overrides remain separate from source facts. Game-specific phrase candidates and static-page answer checks are unmeasured proposals. Authorized exact-page finalized Search Console query rows carry dates, clicks, impressions, CTR and aggregate position; missing/suppressed rows and privacy-filter limitations remain explicit. These are not search-volume, fixed-rank or causal claims.

The existing change workflow requires an already-shipped owner-reported release version, description, HTTPS evidence reference, effective UTC time and explicit half-open baseline/follow-up windows. Comparisons report human-only unique players/sessions, starts, conversion/completion denominators, active-play coverage, returning players and mature D1 cohorts. Follow-up completion and cohort maturity are distinct. Partial windows, low samples, unequal windows, instrumentation, source/device mix, late events and overlapping releases limit interpretation; resolved findings and legacy button clicks do not establish success.
