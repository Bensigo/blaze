# Web game marketing — implementation context

Approved 28 October 2026. Independent product at `/Users/macbook/work/web-game-marketing` with a separate Vercel project. Forever is the intended first integration; work in its own project is separately scoped and its real integration is not yet accepted.

## Product decisions

Web games only. Multi-game workspaces, Google login, server-held user provider keys. Own telemetry SDK. Human traffic is separated from synthetic recordings. Jev selects bounded actions from a game state/action adapter while a browser worker records real gameplay. Video recordings feed a reusable clip library, drafts, review, calendar, and approved publication. Daily in-product jobs inspect discoverability, public research sources, competitors, and telemetry; findings cite observations and distinguish hypotheses. No unreviewed publication, billing plans, spend, paid resource upgrades, or native store optimization.

## Architecture

The in-product research agent uses Vercel AI SDK 7 `ToolLoopAgent` with read-only evidence/history tools, structured proposals, a four-step limit and a 12-second deadline. Content drafts use the same SDK's Anthropic provider with the owner's encrypted key and selected model. Fresh per-game history includes bounded 90-day human aggregates, observed campaign traffic, prior post copy/status, past findings and measured changes. Raw player/session identifiers, credentials and private capture footage are excluded. Missing model access remains an explicit coverage gap; deterministic checks still run. AI suggestions require review, and no model tool can approve or publish. Jev keeps its separate TypeSafe typed-action adapter for gameplay.

Next.js App Router + TypeScript. The approved target is the existing free Neon PostgreSQL project with Neon Managed Better Auth and an owner-configured Google OAuth client. Schema migration 4 was applied to that Neon database; the current source changes have not yet been deployed or accepted. The owner-configured Google client is installed in Neon; the final frontend origin and a real Google sign-in remain unverified. PGlite remains local development/test storage. Neon verifies sessions server-side and maps provider identities to server-owned workspaces; opaque DB sessions are restricted to local development/tests. AES-256-GCM encrypts credentials. The SDK validates game origin, bounds and deduplicates events, and does not accept a browser synthetic flag as proof. A scoped server-issued capability supports synthetic integration; the real Forever round trip remains unverified. The worker has authenticated claim/upload APIs and bounded leases. The earlier public release is still on Vercel. A free commercial host is under measured compatibility review; an independently running worker is needed for continuous browser jobs. Current source supports private Vercel Blob assets and authenticated routes. The private Neon S3 adapter is implemented with direct worker staging uploads and server-only final copies; data-plane acceptance passed, while hosted authorization, playback and worker integration remain pending.

Adding a game durably queues a source-backed profile investigation. Owner overrides are kept separately, and missing evidence or integrations remain visible. Human telemetry can trigger a coalesced profile refresh. Automatic Jev recording defaults to a 24-hour interval only after a prior same-game recording proves real actions and a Jev decision, with a verified key, recent worker heartbeat and investigated profile; the owner can pause it. Actual clips can feed an Anthropic draft when the configured model is available, but drafts require review and are never automatically approved. This readiness is historical evidence, not proof of current provider availability.

## Shared implementation boundaries

`src/lib/types.ts` owns view contracts. `GET /api/workspace` returns WorkspaceSnapshot. `POST /api/actions` accepts `{action,...}` and returns updated data or error. Supported actions: add_game, update_game, queue_recording, create_clip, create_post, update_post, submit_review, approve_post, publish_post, delete_post, save_connection, delete_connection, run_research, update_finding. UI refreshes snapshot after mutations. Readonly illustrative demo uses `/api/demo` and carries `demo:true`; it is not real analytics. Production authentication without Google keys is a visible configuration dependency; local-only development login supports acceptance without exposing production bypasses.

Authorized exact-page finalized Search Console query rows carry dates, clicks, impressions, CTR and aggregate position; missing/suppressed rows and privacy-filter limitations remain explicit. These are not search-volume, fixed-rank or causal claims.

The existing change workflow requires an already-shipped owner-reported release version, description, HTTPS evidence reference, effective UTC time and explicit half-open baseline/follow-up windows.
