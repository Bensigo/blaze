# Integration setup and boundaries

Credentials are held encrypted server-side. The source implements provider authorization, callback, refresh and disconnect flows for X, YouTube, Instagram and TikTok, with explicit manual-token fallback. Provider configuration, account identity, scopes, refresh behavior and publication must still be validated with real authorized accounts. Some revocations cannot be confirmed through the provider API. Do not expose tokens, media upload URLs, response bodies, or secret query strings in logs.

- **Jev (TypeSafe)**: enter a TypeSafe API key. `GET /v1/models` verifies access only; a real decision and gameplay require the worker and its structured state/action adapter. [TypeSafe API](https://api.typesafe.ai/redoc).
- **Anthropic**: enter an API key and an available model name; some keys additionally need a workspace ID. Model listing tests access. The Vercel AI SDK Anthropic provider powers drafts and the bounded daily research agent and incurs provider usage. Each request reloads game-scoped historical results; the model has read-only evidence/history tools and cannot approve or publish. Missing credentials or model failures appear in research coverage. Live model acceptance requires a real owner key; SDK/provider tests use controlled responses. Output requires human review. [AI SDK Anthropic provider](https://ai-sdk.dev/providers/ai-sdk-providers/anthropic), [Authentication](https://platform.claude.com/docs/en/manage-claude/authentication).
- **X**: authorize a user token with the relevant read, write and media access for your developer app. Account verification does not verify posting or recent search entitlements. Video goes through v2 chunk upload and processing before a separately reserved create-post step. API access and pricing are external dependencies. [Media upload](https://docs.x.com/x-api/media/quickstart/media-upload-chunked).
- **Brave Search**: optionally enter a Brave Web Search API key under provider `brave`; the connection check and research queries consume provider quota. Genre-based search surfaces possible pages for review, including directories or non-playable pages; it does not establish a competitor or traffic. [Web Search](https://api-dashboard.search.brave.com/app/documentation/web-search), [authentication](https://api-dashboard.search.brave.com/documentation/guides/authentication).
- **Reddit**: provide an authorized OAuth token with account identity and read/search access under Reddit's terms. Research uses the authorized API only; disconnected or denied sources are shown as coverage gaps. Search results are leads, not proof of relevance or sentiment.
- **YouTube**: authorize the channel with an upload scope. Video bytes come from private storage; this adapter caps media at 50 MB. Upload acceptance is processing, not publication. A public, successfully processed video is verified through `videos.list`. Some unverified API projects are subject to private upload restrictions. [Upload](https://developers.google.com/youtube/v3/docs/videos/insert), [processing](https://developers.google.com/youtube/data/guides/implementation/videos).
- **Instagram**: use an Instagram professional account and a suitable Instagram Login token and content-publishing permission. Meta must fetch a short-lived HTTPS URL for the exact clip; the normal authenticated app media route is insufficient. Create a Reels container, check until FINISHED, then reserve a distinct durable publish operation; verify the resulting media permalink. Do not automatically repeat an uncertain publish call. [Instagram API](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing/).
- **TikTok**: an approved app, user token with `video.publish`, creator-info query, supported per-post privacy and interaction controls, and explicit per-post consent are required. A user interface must bind these choices and consent to the approved content before invoking the adapter. The saved credential cannot authorize the consent on its own. Unaudited apps face visibility restrictions and public posting requires audit. The adapter uses single-chunk file upload capped at 50 MB. [Direct Post](https://developers.tiktok.com/docs/en/content-posting-api-reference-direct-post), [status](https://developers.tiktok.com/docs/en/content-posting-api-reference-get-video-status), [guidelines](https://developers.tiktok.com/docs/en/content-sharing-guidelines).

## Neon Managed Better Auth and Google sign-in

Enable Managed Better Auth on the intended Neon branch. Set server-only `NEON_AUTH_BASE_URL`, a random `NEON_AUTH_COOKIE_SECRET` of at least 32 characters, pooled `DATABASE_URL` and canonical `APP_URL`. Register `<NEON_AUTH_BASE_URL>/callback/google` as the Google web client's authorized redirect URI and add the app origin as a Neon trusted domain. Configure the owner's Google client ID and secret in Neon, then set `NEON_AUTH_GOOGLE_CONFIGURED=true`. Do not enable production with Neon's shared development Google credentials. Follow Neon's production checklist, including disabling localhost access when appropriate and configuring Google consent/verification as required. See [Neon OAuth setup](https://neon.com/docs/auth/guides/setup-oauth) and [production checklist](https://neon.com/docs/auth/production-checklist).

Neon's official Next.js SDK handles the browser challenge and session verifier exchange. The server validates the session upstream and maps its verified user ID to a server-owned workspace; editable metadata and email do not select a workspace. Neon IDs are namespaced, so earlier identities are not automatically linked by email. Production rejects local development sessions. The local SDK's Better Auth dependencies use aligned patched overrides; those overrides do not establish the patch level or plugin configuration of Neon's managed service. Confirm the managed service's status against [GHSA-965c-763c-88jm](https://github.com/advisories/GHSA-965c-763c-88jm) and [GHSA-r4xp-prcw-77qf](https://github.com/advisories/GHSA-r4xp-prcw-77qf) before enabling sign-in. Controlled tests do not establish a real Google login.

## Operational contract

The application owns workspace isolation, encrypted secrets, approval hashes, scheduling, durable reservations and idempotency. Adapter functions do not authorize publication. A result of `processing` without an ID after a write means the outcome is unknown: reconcile manually, never retry creation blindly. The X and Instagram staged flows use a separate durable reservation for the final publish step. The source includes OAuth onboarding and provider-specific refresh/disconnect handling, plus short-lived signed media transfer where required; provider webhooks and external account audits are not implemented. No real social account or posting acceptance has been demonstrated.

Manual delivery is a separate fallback. An owner selects an unverified destination, reviews and approves exact text, clip, destination, delivery method and schedule, then prepares a caption and downloads the private clip through an authenticated route. Preparing, copying or downloading does not mark the post published. The owner can record a URL and actual time as a user-confirmed, provider-unverified publication. Edits clear approval and manual confirmation; manual posts are excluded from native dispatch. Channel and time suggestions explicitly state their limited observational or cold-start basis.

Research checks the public game page, up to three configured competitor pages, robots.txt, sitemap.xml, and authorized X, Reddit and optional Brave search APIs. Title and genre queries are separate; a search match may have nothing to do with the game. A discovered URL is a candidate for human review. Static HTML text and single-fetch timing are not search ranking or real-user performance. Robots directives are displayed without attempting full crawler-specific precedence or path interpretation; meta and HTTP X-Robots-Tag restrictions are observations, not indexing proof. Same-run comparisons are not a historical baseline. A dated historical page snapshot must be supplied by the caller to compare across time. Human session evidence links to workspace-scoped event data; a last step in a session with an error is not necessarily the error event. See [Google robots directives](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) and [robots.txt matching](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec). Public fetches are IPv4-only, resolve and pin public addresses, reject private/reserved addresses and credentials, revalidate redirects, and enforce timeout/size limits. The robots and sitemap checks establish HTTP availability only; they do not prove crawling, ranking or indexing. A result may match a generic game name without referring to this game. Telemetry findings reflect supplied human data, not causality or competitor private traffic. Failures and disconnected sources remain visible in coverage.

No live provider write or publication was performed during implementation. Fixture tests intercept network requests; real account authorization, scope, media format, platform compliance and end-to-end posting still require owner acceptance.

**Google Search Console:** Supply an authorized user access token with the `https://www.googleapis.com/auth/webmasters.readonly` scope and choose the exact accessible property URL or `sc-domain:example.com` as the account ID. The connection check lists accessible properties; it does not create an OAuth grant or refresh an expired token. The research report requests finalized Google web-search metrics for the exact registered game URL, comparing two inclusive 28-day windows ending three Pacific calendar days ago. Google may report a different canonical URL, delay finalization or omit a row; missing data is not treated as zero. Clicks, impressions, CTR, and average position are Search Console aggregates, not private competitor traffic or proof of causality. See the official [sites list](https://developers.google.com/webmaster-tools/v1/sites/list) and [Search Analytics query](https://developers.google.com/webmaster-tools/v1/searchanalytics/query).
