# Recording worker

The worker runs separately from the web server and polls for leased jobs. Install dependencies and Playwright Chromium (`npx playwright install chromium`), set `APP_URL` and `WORKER_TOKEN` in its environment, then run `npm run worker`. For a Vercel-hosted app with Blob configured, also set `BLOB_CLIENT_UPLOAD=true` on the worker so large assets upload directly to private Blob storage; local development uses multipart uploads to the app. Use HTTPS for a remote app. Keep the worker token and the owner's Jev key out of game pages, logs and source control. The server supplies the encrypted-at-rest Jev credential only in an authenticated claim. With no key, a Jev recording fails explicitly. The implementation calls TypeSafe's [System One API](https://api.typesafe.ai/redoc) with a bounded choice; live Jev behavior requires validation with a real key.

The game must provide the adapter in SDK.md. Actions and state must be safe to share with the configured model. The worker uses a 30-action/30-second loop, request and adapter timeouts, a lease heartbeat, real Playwright video and screenshots, and authenticated uploads. It accepts only public HTTPS game hosts with public IPv4 addresses, pins the resolved address in Chromium and blocks cross-origin traffic, service workers, WebSockets, and downloads. This means games requiring external CDNs or WebSockets will need a future reviewed network policy; they may not run now. Use an isolated worker host and network egress restrictions as defense in depth; the adapter executes code from the game's page, so only record games you trust. External keys never enter the browser page.

For local acceptance only, set `ALLOW_LOCAL_FIXTURE=true` and add the exact URL `http://127.0.0.1:3000/fixture/index.html` as a game. Fixture mode only permits this app’s controlled fixture at `/fixture/index.html` (including its public HTTPS deployment), uses deterministic moves, and is labeled as such. It does not validate Jev. The fixture can also be played with buttons, arrow keys and Enter. Synthetic events use the authenticated worker route; ordinary SDK calls remain human traffic.

Clips are generated by ffmpeg from the actual recording, with aspect-preserving letterbox/pillarbox for landscape, portrait and square. Source and output are temporary files removed after each job; assets must be stored by the server in persistent storage. The worker does not publish social posts. A running worker, configured persistent asset storage, and a reachable authorized game are operational dependencies; serverless deployment alone does not run browser jobs.

Recording observations contain timestamped adapter phase changes, action and model-decision counts, the last observed phase, and whether completion was observed. Only a small vocabulary of phase and error names is retained; other values become unclassified rather than being copied from game state. A repeated unchanged state is a hypothesis to review, not a diagnosis. Page errors use bounded error categories and stable telemetry codes; messages, URLs, input text and credentials are excluded. Blocked external requests and WebSockets are reported as worker coverage limits, not game errors. A final-frame observation is timestamped when its screenshot was captured. On failure the worker attempts to save observations while its lease remains valid.
